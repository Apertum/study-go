# internal/config

В этом пакете хранятся конфигурации приложения.

Загрузку конфигурации можно реализовать из различных источников, например: файлов, переменных окружения, баз данных и других.

Сервер читает конфигурацию в `ParseFlags()` из `main()`: флаги командной строки, переменные окружения и
JSON-файл. Значение каждой настройки берётся из старшего непустого источника:

**непустая переменная окружения > явно переданный флаг > файл > значение флага по умолчанию**

Флаг считается переданным явно, только если он указан в команде, — даже когда его значение совпадает со
значением по умолчанию: `-a :8080` старше `"server_address"` из файла. Пустая строка в переменной и в
файле означает «источник молчит».

## Настройки сервера

| Флаг | ENV | Ключ файла | По умолчанию | Эффект |
| --- | --- | --- | --- | --- |
| `-a` | `SERVER_ADDRESS` | `server_address` | `:8080` | адрес основного слушателя: HTTP либо HTTPS |
| `-b` | `BASE_URL` | `base_url` | `http://short.ru/` | базовый префикс коротких URL |
| `-f` | `FILE_STORAGE_PATH` | `file_storage_path` | `data.json` | файл хранения, когда база данных не подключена |
| `-d` | `DATABASE_DSN` | `database_dsn` | пусто | DSN PostgreSQL; пусто — работать по файлу |
| `-k` | `COOKIE_KEY` | `cookie_key` | `thisSuoerSecretMyKey` | ключ HMAC-SHA256 подписи куки `user_id` |
| `-audit-file` | `AUDIT_FILE` | `audit_file` | пусто | путь к файлу аудита (JSONL) |
| `-audit-url` | `AUDIT_URL` | `audit_url` | пусто | URL приёмника аудита |
| `-s` | `ENABLE_HTTPS` | `enable_https` | `false` | включить HTTPS и редирект с HTTP |
| `-cert-file` | `CERT_FILE` | `cert_file` | `cert.pem` | PEM-сертификат TLS; выпускается сам, если отсутствует |
| `-key-file` | `KEY_FILE` | `key_file` | `key.pem` | PEM-закрытый ключ к `-cert-file`, права `0600` |
| `-http-addr` | `HTTP_SERVER_ADDRESS` | `http_server_address` | `:8081` | адрес HTTP-слушателя редиректа на HTTPS |

## Файл конфигурации

Путь к файлу задаётся флагом `-c` (он же `-config`) либо переменной `CONFIG`; непустая переменная
переопределяет флаг. Значения по умолчанию у пути нет: без `-c`, `-config` и `CONFIG` файл не читается
вовсе, а поведение совпадает с запуском без файла.

```json
{
    "server_address": "localhost:8080",
    "enable_https": true
}
```

Полный пример без секретов — [testdata/config.example.json](testdata/config.example.json). Сохраните его
копию, поправьте значения и добавьте нужные ключи из таблицы выше — соответствие «ключ файла | флаг | ENV»
там же.

Файл — строгий JSON без расширений синтаксиса. Комментарии `//` и `/* */`, хвостовые запятые, одинарные
кавычки и любые иные вольности делают файл неразобранным: сервер напечатает предупреждение и продолжит
запуск без настроек из него. Символы внутри строкового значения — часть значения, поэтому
`"base_url": "http://localhost"` читается как есть. Неизвестные ключи игнорируются молча. Пустой файл или
файл из одних пробелов — не ошибка: он не задаёт ни одной настройки.

Пустое значение ключа (`""`) означает «настройка не задана», поэтому из файла нельзя задать пустой адрес
или пустой базовый префикс вместо значения по умолчанию.

Ошибки файла (нет файла, не читается, не разбирается) запуск не прерывают: в журнал попадает
предупреждение `конфигурация из файла не применена: <-c|-config|CONFIG>=<путь>: <причина>`, а настройки
приходят из флагов, переменных и значений по умолчанию. Частичных значений из неразобранного файла не
бывает. Код разбора печатает только способ задания пути, сам путь и причину отказа; существующие строки
`ParseFlags()` — `Read addr`, `Read base`, `DSN для подключения к PostgreSQL` — печатают итоговые значения
независимо от источника. Секретные `cookie_key` и `database_dsn` в профиль репозитория не кладут: права на
файл остаются зоной ответственности запускающего.

## Включение HTTPS

Значение `ENABLE_HTTPS` разбирает `ParseFlags()` этого пакета: переменная приоритетнее флага `-s` и ключа
файла `enable_https`; допустимы `1`, `t`, `TRUE`, `true`, `True`, `0`, `f`, `FALSE`, `false`, `False`.
Другое значение завершает процесс до прослушивания портов и до прочих побочных эффектов запуска — файл
аудита не создаётся, подключение к базе не выполняется; в сообщении именем переменной остаётся её значение.
Функция `ParseEnabled` остаётся экспортной — её вызывает клиент `cmd/shortener` со своим набором флагов.

Материалы TLS, параметры слушателей редиректа и проверку их совпадения делает пакет
[`internal/secure`](../secure/doc.go): `go doc ./internal/secure`.
